# Product contract

**Maturity: SPECIFIED.** Rewrotron is a local-first, open-source, vendor-neutral application reconstruction engine. CI3 → Laravel is a planned reference path, not the definition of its universal core. It migrates behavioral vertical slices while preserving approved externally observable behavior and permits explicit architectural improvement and intentional behavior changes.

## Defensible claims

Rewrotron preserves what the approved contracts specify and continuously shows its work and evidence. It does not infer full-application certainty from a generated passing corpus. Every claim identifies source snapshot, observation/operational profile, environment, corpus, executable contracts, comparator/normalization policy, resolved target and evidence scope. [BEHAVIOR-MODEL](../02-domain/BEHAVIOR-MODEL.md) defines observed/contract/semantic equivalence, unknown/unverified/unsupported behavior and intentional changes. Semantic equivalence is an obligation to demonstrate under named semantics, never a blanket certification.

Discovery inventories HTTP, CLI, cron, jobs, callbacks, files and stateful workflows. Browser execution, streams, unconstrained concurrency and opaque native behavior require declared capabilities; absent support remains UNKNOWN/UNSUPPORTED. User-supplied critical workflows and an independently reviewed operational inventory are necessary evidence. The corpus cannot establish its own completeness.

## Control and reproducibility

Detect → show → explicit persisted Gate 1 → shared analyze/observe/model → assessment report → explicit user decision → resolve selected work into an executable plan → show → explicit Gate 2 → staged migration/isolated verification/repair → scoped acceptance → performance evidence → explicit Gate 3 release package. [Lifecycle](../02-domain/PROJECT-LIFECYCLE.md) owns transitions. No production runner is implied.

Facts, assertions, recommendations, intent, exact resolution and approvals remain distinct. User versions are never downgraded by an agent. Unknown dependencies or missing runtime capabilities block affected scope before generation. Decisions and consumed revisions are immutable; progress is separate. Exact engine/build/schema bytes and applicable control qualifications are part of the retained approval closure, owned by CONFIRMATION-PROTOCOL. [Target specification](../04-migration/TARGET-SPECIFICATION.md) owns configuration.

The engine works deterministically without an LLM for supported analysis/replay/acceptance operations. Agents may propose code and hypotheses through CLI/MCP/Skills; acceptance is independent. Local-first describes default storage/execution, not prevention of external clients sending data. [Security](../09-security/SECURITY.md) defines trust and export boundaries.

## Product acceptance

The first meaningful experiment must reject plausible wrong reconstructions: missing writes, wrong principal, duplicate effects and incomplete capture. A read-only route is a smoke test only. The [roadmap](../11-roadmap/ROADMAP.md) gates wider implementation on falsification evidence. No adapter/client/release claim precedes its runtime/integration/release evidence.

Assessment-only use stops successfully at the [shared assessment checkpoint](../02-domain/PROJECT-LIFECYCLE.md), including when feasibility is BLOCKED/UNKNOWN or runtime evidence is unavailable. Reports preserve provenance, static-only limitations and uncertainty. Later continuation reuses only currently valid findings; completing or reviewing a report never authorizes implementation.
