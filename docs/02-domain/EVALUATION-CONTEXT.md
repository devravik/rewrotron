# Evaluation context ABI 1.0

**Owner:** Projection of immutable fixture, shadow and captured values for the bounded evaluator. [BEHAVIOR-MODEL](BEHAVIOR-MODEL.md) owns operators and roles. [evaluation-context.schema.json](../../specs/behavior/evaluation-context.schema.json) fixes the closed record shape. This is SPECIFIED, not an implemented interpreter.

## Identity, phases and provenance

Each immutable context names project/context/side, occurrence_id (physical ID, not a future artifact ref), projection_ref (exact qualified projector), phase, origin and evidence_refs. Phases FIXTURE, PRE_OPERATION, POST_OPERATION, COMPLETION, SIMULATION. FIXTURE uses FIXTURE_PREPARED; SIMULATION uses MODEL_EXPECTED; other phases use ACTUAL_OBSERVED. No parent/future paired case is required for source discovery. Side is SOURCE/TARGET/SHADOW; SHADOW is simulation only. The read-only checker accepts ACTUAL_OBSERVED only. Fixture and shadow contexts may help construct expectations but cannot satisfy actual obligations. All non-missing projected values must be justified by projector output plus capture provenance; the service checks trusted channel, witness, scope and exact source paths. A hash/reference is not sufficient evidence authority.

## Typed values and pointer resolution

Values are tagged {type,value}: string, boolean, integer (canonical exact signed decimal string), decimal (exact base-10 string), timestamp (RFC3339), bytes (registered private/sanitized byte ref), null, object (map of tagged children), array (ordered tagged children). MISSING is {type:"missing",reason_code}; it has no value. Transport integers have no rounding/64-bit restriction; arithmetic keeps BEHAVIOR-MODEL bounds. Decimals never use binary floats; exponent JSON spellings are converted exactly into coefficient/scale subject to bounds. Duplicate JSON object keys, undecodable body or exceeded limit yields MISSING/unsupported, not a best-effort value. Binary and unsupported non-UTF8 HTTP data remain bytes refs and cannot become a text predicate. Lossless byte replay outside declared text capabilities is UNSUPPORTED.

Expressions name a namespace and RFC6901 pointer relative to that namespace. User-facing full paths such as /result/body/order_id mean namespace=result, pointer=/body/order_id. Traverse tagged object/array value containers transparently, checking each tag; an intermediate wrong type is ERR_TYPE, missing/unavailable is MISSING. Empty pointer selects the whole namespace. No pointer reads another phase, origin or side implicitly. Scalar access unwraps the tag to the expression's declared type. /result/body/order_id therefore selects the exact parsed JSON member in the current side's measured response, never a model response or DB guess.

Actual effective input bytes; available pre/post/completion. Parsed query uses the pinned UTF8 RFC3986 projector; repeated keys remain separate. |
| actor | fixture_actor_ref and actual_principal (MISSING before observed authentication). Actual principal contains authentication status, subject side-local ID, observed session ID, role values and channel/evidence refs. Labels and intended credentials are not actual_principal. |

PRE uses independently observed before state, POST uses after state, COMPLETION uses state at the completion boundary. |

Body parses only under approved content-type/projector; HTML/binary stays bytes until a qualified provider exists. |
| binding | Single-assignment tagged values from declared actual preceding occurrence projections; shadow bindings exist only in SIMULATION. Token values remain private/in-memory with approved correlation projection. |

Headers/cookies follow response.schema; session/cache payloads follow effect-payload.schema. DB rows use discovered qualified data-model types. Empty collections require positive capture evidence; MISSING denotes unknown/unavailable and is distinct from observed null. Unknown principal is not anonymous; anonymous is an observed authentication outcome. Context initial state is built from [initial-state.schema.json](../../specs/behavior/initial-state.schema.json); the fixture actor is [principal-fixture.schema.json](../../specs/behavior/principal-fixture.schema.json). These private fixtures bind intended credentials/stores; only actual observed auth supplies actor.actual_principal.

## Phase use and invalidation

PRE_OPERATION can read input, actor/state/clock observed before the operation, prior bindings; result is MISSING. POST_OPERATION exposes actual synchronous output/state; async values remain unavailable until COMPLETION. Transition guards use the completed occurrence's committed actual context independently per side. Step guards are the reserved literal true defined in BEHAVIOR-MODEL; they do not implement conditional skipping. Model simulation uses its own SHADOW context, never fills a missing actual value. Assertions cannot switch context origin. Source-only context publication precedes any target/case. Pairing and comparison produce new artifacts without editing contexts.

Projector/schema/capture/profile/principal/fixture changes invalidate consumed descendants through typed coverage. Retain old context bytes and exact schema/projector identities; current execution never silently reinterprets them. JSON Schema validates shapes; trusted-service checks enforce values, namespace phase rules, provenance and correspondence. X61–X67/X77 falsify write contamination, projection poisoning, principal substitution and wrong response lowering. Infrastructure failure is UNKNOWN/refusal, not a semantic mutation kill.

Context evidence_refs point to prior capture fragments/witnesses, not a future trace or paired result. result.effect_refs point to prior typed payloads; step-occurrence then references pre/post contexts; delivery-occurrence references the step; effects/trace publish last. This order prevents context → effect → step → context hash cycles. Namespace-level null input/result/row means unavailable namespace, equivalent to MISSING on traversal; an observed JSON null is always the tagged null value. FIXTURE contexts use intended actors and measured authentication remains MISSING.

Record metadata leaves have types fixed by this schema: native status/count integers project as exact integer values, booleans as boolean, text/enums as string, and date-time fields as timestamp. Business payload numbers must use tagged integer/decimal strings; native JSON numbers there are invalid. Null in unavailable namespace positions is MISSING; nullable observed cookie attributes/query values mean observed absence and project as typed null. Session/cache/queue/file state values must match the pinned state/profile shape and payload schemas; open object member names are application-defined, but every value remains tagged and typed. Projection errors never fall back to model values.

The typed response headers list excludes Set-Cookie; cookies preserve their own ordered occurrences. Raw trace header evidence preserves original wire order. Cross-list interleaving assertions are outside the initial lowering capability and block when required. Named cookie attributes are the supported set; unknown required extensions/partitioning semantics remain UNSUPPORTED. The raw response is retained under its privacy rules rather than flattened into supported attributes.

## Raw JSON numeric projection (B3)

This rule applies to numeric tokens in an approved JSON body/payload projector, before host-language number decoding. A token with neither decimal point nor e/E projects as integer; any token containing a decimal point or e/E projects as decimal, even if mathematically integral. Thus `1` → integer "1", while `1.0` and `1e0` → decimal "1". Token grammar is JSON number grammar, not a language's permissive numeric parser. Invalid grammar/duplicate keys fail the JSON projection; they are never coerced. Retain raw bytes for raw comparison.

Decode sign, coefficient and exponent exactly, without binary floating point. Canonical integer spelling has no leading zeros or negative zero. Decimal spelling is ordinary base-10 without exponent, trailing fractional zeros, a trailing point or negative zero; preserve the decimal tag after normalization. `-0` → integer "0"; `-0.0` → decimal "0"; `1e-2` → decimal "0.01". For canonical decimals, the coefficient formed by removing the decimal point and leading zeros has at most 38 digits (zero counts as one); scale has at most 18 fractional digits after trailing-zero removal. Exceeding either bound yields {type:"missing",reason_code:"ERR_UNSUPPORTED_CAPABILITY"}, never rounding or retagging as integer. These are the BEHAVIOR-MODEL decimal bounds made explicit; integer transport remains arbitrary precision subject to the qualified input resource limit, separate from executable signed-64 arithmetic. Resource-limit failure is incomplete/unsupported, not numeric substitution.

The current context schema accepts only canonical integer/decimal spellings. Model literal artifact spellings stay unchanged for hashing and are normalized only during exact evaluation, as BEHAVIOR-MODEL specifies. Typed equality has no implicit cross-type coercion: integer "1" compared to decimal "1" is ERR_TYPE/UNKNOWN, not true or false; only the explicit INTEGER_TO_DECIMAL operator changes that. Decimal "1" and decimal "1.0" literals evaluate to the same numeric value. A projector cannot choose a tag from a DB schema, expected outcome or host float. Native context metadata retains its schema-fixed types. Semantic comparison consumes this typed projection; any intentional numeric equivalence policy must be separately approved and pinned, never inferred.

[contract-blocker-vectors.json](../../specs/examples/contract-blocker-vectors.json) contains raw tokens, canonical tags/values and invalid/bounds mutations for X21/X63. The structural checker validates golden spellings/shapes; eventual projector/evaluator behavior must reproduce them.
