## 1. Target Design Principles

Target applications generated by Rewrotron must be idiomatic, maintainable, and completely independent of Rewrotron runtime artifacts.

### Architectural Blueprint (Laravel 13 Example)
```text
laravel-target/
├── app/
│   ├── Actions/                  # Single-responsibility business actions
│   │   └── Orders/
│   │       └── CreateOrderAction.php
│   ├── Http/
│   │   ├── Controllers/          # Lean HTTP routing coordinators
│   │   │   └── OrderController.php
│   │   ├── Requests/             # Form validation & authorization
│   │   │   └── CreateOrderRequest.php
│   │   └── Resources/            # API response transformations
│   │       └── OrderResource.php
│   └── Models/                   # Eloquent relational models
│       ├── Order.php
│       └── OrderItem.php
├── database/
│   └── migrations/               # Retained / mirrored database schema
├── resources/
│   └── views/                    # Clean Blade templates
└── tests/
    └── Compatibility/            # Retained differential verification tests
```

### Invariants:
1. **No God Controllers:** Controllers only validate incoming requests (via Form Requests), delegate execution to Actions/Services, and return view/resource responses.
2. **Explicit Database Transactions:** Transaction boundaries are modeled explicitly in Actions (`DB::transaction`).
3. **Type Safety:** Target code uses strict types (`declare(strict_types=1);`), typed properties, and explicit return types (PHP 8.3+).
