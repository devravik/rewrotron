# Differential replay and scoped acceptance

**Owner:** Replay protocol and acceptance aggregation. [COMPATIBILITY-SPEC](COMPATIBILITY-SPEC.md) owns comparison semantics; [MIGRATION-UNITS](../04-migration/MIGRATION-UNITS.md) owns the three scopes.

## Independent environments

Source and target never share writable verification databases, Redis/session namespaces, files or effect endpoints. “Same MySQL initially” means preserved production schema/behavior, not one test database. Each side starts from independently restored equivalent fixture state and a recorded reset report. [DATABASE-COMPARISON](DATABASE-COMPARISON.md) defines multi-connection reset. Each workflow preserves its side's state across steps; each fresh scenario restores all dimensions.

Pin source snapshot, profiles, exact runtime/build, contract/corpus/policy, probes/comparators/runners and target tree. Raw HTTP targets/ordered headers/body refs preserve empty/repeated/query distinctions. Core parses large business numbers exactly; machine clients send immutable raw bytes refs or typed strings, not rounded JSON values. Match logical identities relationally across DB/response/links/effects and actor partitions.

## Protocol

Verify readiness/fences/gates, reset both sides, check isolation controls and capture controls, execute bounded steps/guards/bindings, await declared async completion, collect attestations and state/effects, compare under approved policies, publish immutable per-case and scoped reports transactionally. Every trace uses the canonical causality envelope. Limit/truncation/missing mechanisms remain incomplete. SQL rollback alone is not a reset certificate.

Known disagreement produces MISMATCH; insufficient/unavailable required evidence produces UNKNOWN; PASS requires all required assertions and dimensions. Intentional changes are approved comparison-policy obligations with explicit difference reporting, not a fourth verdict or unknown waiver. Run reports contain acceptance_scope/corpus/plan/target/profile identities. UNIT excludes unimplemented future dependents; implemented regressions check current affected components; PROJECT requires the full approved in-scope corpus. Aggregation cannot count duplicate case rows, old target results or excluded cases as current PASS.

## Oracle independence

Before acceptance, test negative targets missing a DB write, switching owner identity, duplicating effect, returning a wrong redirect, mishandling token lifecycle and suppressing a capture dimension. Approved normalizers must retain these failures. Expected behavior is reviewed against source observations, supplied critical cases and independent holdouts; it is not established solely by the generator's own tests. When observation cannot safely reach production-only/opaque/irreversible behavior, report a blocker or explicit unsupported/excluded scope.

Current 2.1 reports populate every dimension with applicable/verdict/reason/evidence refs. Not-applicable has verdict=null and contract justification; applicable dimensions have only the three verdicts. PASS cannot contain an applicable UNKNOWN/MISMATCH or zero cases. Service checks additionally require the exact corpus scope and cannot accept an agent-selected not-applicable flag. The legacy v1 report dimension shape had an impossible `$ref` requirement; it is historical non-executable data, never a current report contract.

## Measurement boundary and occurrence pairing

Before measurement, restore approved initial-state fixtures with a distinct FIXTURE_PREPARED witness and capture independent before state. Seal fixture access. During measurement only ApplicationRunner can cause application mutations; ScenarioDriver sends declared inputs, ShadowSimulator uses separate stores, Observer records actual effects, AssertionEvaluator/Comparator have read-only measured access. Capture and assertion contexts use ACTUAL_OBSERVED. Expected db_write/emit/set_state/transaction actions are never sent to measured stores. Audit denied checker writes and prove X61's missing row stays missing. No expected value fills unavailable capture.

A logical workflow occurrence belongs to one approved scenario invocation; each step occurrence is (logical_workflow_id, step_id, visit ordinal). Initial acyclic/unrolled graphs have ordinal 1 per declared step; repeated identical requests at different steps remain different occurrences. Each side records its own physical occurrence, actual guard outcomes, chosen transition, context ref and terminal. Occurrence records are immutable; pairing references them afterward. Common approved inputs/principal fixtures establish the logical pairing, never timestamp or array index.

Current continuation policy is STOP_AT_FIRST_DIVERGENCE: compare the last corresponding operation/outcome and next transition. Same branch continues; differing established branches or one unexpected/early terminal is MISMATCH with first_divergence and both actual contexts preserved. Stop issuing downstream business requests on both sides, record unmatched occurrences as NOT_COMPARED, and perform witnessed cleanup only (cleanup is not application behavior). No fabricated alignment/forcing the source branch on target. Unknown guard yields UNKNOWN and no further business requests unless an already independently established violation takes precedence. Missing capture/witness is infrastructure UNKNOWN/refusal; a known wrong branch under valid capture remains semantic MISMATCH. Diagnostic independent continuation is deferred, never contributes PASS.

Current report 2.1 names occurrence-pairing and pairwise identity map per case, alongside traces; maps 2.1 name both side ledgers. Service requires distinct SOURCE/TARGET roles, compatible scenario/case/input/profile and separate witnessed environments/builds. Source-vs-source comparison is ERR_INVALID_COMPARISON/UNKNOWN regardless of byte similarity. Both execution witnesses must bind the plan's approved original/variant/resolution and current target tree. A PASS requires all comparisons supported and paired; no unmatched required occurrence, expected-only effect or stale build can count. X62/X64/X65/X66/X80 are controls of these prerequisites.

For report 2.1 infrastructure UNKNOWN, unavailable trace/map/pairing refs are explicit null with required dimension reasons/errors; never synthesize a trace to satisfy a schema. PASS requires both actual traces and current pairing/map; MISMATCH requires independently established actual evidence on both sides, though unrelated ambiguous identity work may remain null/UNKNOWN. No missing correspondence can be counted as verified.
