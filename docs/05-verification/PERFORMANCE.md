# Performance claims and statistical acceptance

**Owner:** Workload, statistical claim, immutable performance policy and benchmark outcome. Applicable scope must have current behavioral parity before measurement. Performance cannot compensate for skipped behavior. This specification is not executed benchmark evidence.

## Approval-bound policy

Before Gate 2, PLAN decision_refs includes exactly one [performance-policy.schema.json](../../specs/verification/performance-policy.schema.json) record. It binds project, applicability, claim, exact workload/environment/method, measurement profile, unique required metrics with units/limits/minimum samples, maximum error rate, rationale and evidence. IMPROVEMENT uses strict ratio limit 1; NON_INFERIORITY uses explicitly approved positive margins (limit >1); APPROVED_BUDGET uses explicit absolute and/or relative limits. No automatic allowance exists. Not-applicable is an evidenced human-reviewable decision with null claim/measurement refs and no required metrics; it cannot be inferred from missing instrumentation. Changing policy creates a successor plan/approval and invalidates affected benchmark/release claims.

Current benchmark version 2.2 names performance_policy_ref. Service checks exact equality of project/PLAN closure, claim, workload, environment, method, required metric set/units/limits and budget_decision_ref. For budget claims budget_decision_ref equals the same approved policy ref. Version 1.0/2.0/2.1 benchmark records remain historical-readable, not current acceptance. Mutable latest policy and agent-proposed budgets cannot authorize a report. A not-applicable policy permits an explicitly scoped release without a performance claim, never a fabricated accepted benchmark.

## RWT_PAIRED_BOOTSTRAP_1

Pin workload/fixtures/profile, environment bytes, CPU/memory quotas, runtime/workers, concurrency, cache/clock, target tree and comparator. Use exactly the policy’s predeclared N paired trials (10 ≤ N ≤ 20), alternating source/target order; 30-second warm-up and at least 60-second measured blocks. Stop at N, never at the first favorable confidence interval. An interrupted/failed trial is retained; missing N complete qualifying pairs makes the attempt INCONCLUSIVE. A rerun is a new retained attempt, not selective replacement of unfavorable trials. Startup has separately identified cold/warm trials with owned reset controls. Publish all paired observations, failed requests and measurement controls. Unsupported workloads/methods are INCONCLUSIVE until a successor qualified method is approved.

For each metric take the mean of its per-trial values: latency metrics are the mean of trial-level p50/p95/p99, not a pooled application-wide percentile; RSS_MEMORY is the mean of trial peak RSS; CPU is per-success CPU seconds; counts/DB latency/external latency/response size are per-success means; startup is trial startup elapsed time. Quantiles use nearest-rank ceil(p*n) on ordered successful samples. The approved workload fixes arrival/concurrency/reset and error handling; cannot omit failures or change success populations to improve a metric. Report both sides' error rates; either side above max_error_rate prevents acceptance.

The ratio estimand is mean(target trial values)/mean(source trial values), not a mean of ratios. For absolute budgets it is mean(target trial values) in native units. Resample paired trial indices 10,000 times with stored seed using the pinned method implementation. For replicate r and draw d (both zero-based), hash UTF-8 `rwt-paired-bootstrap-1:<seed>:<r>:<d>:<attempt>` with SHA256, starting attempt=0. Interpret the digest as unsigned big-endian x; reject x ≥ floor(2^256/n)*n and increment attempt, otherwise select index x mod n from the original n paired trials. This pins random selection without a host-language PRNG dependency. Two-sided percentile intervals use nearest-rank endpoints alpha/(2*k) and 1-alpha/(2*k), alpha=0.05, k=all required metrics. Do not resample autocorrelated individual requests or drop unfavorable trials. A zero source mean makes a relative metric INCONCLUSIVE; use a separately approved absolute budget instead. Unknown inter-trial dependence, missing observations or unsupported noise assumptions are INCONCLUSIVE; the bootstrap is an explicitly bounded model, not a distribution-free guarantee.

Required p50/p95/CPU/memory claims need at least 500 successful requests on each side of each measured trial; p99 needs at least 10,000. The policy may raise these requirements; lowering them needs a new qualified measurement profile, not an arbitrary minimum_samples override. Other per-success metrics require the policy minimum and complete instrumentation. DB/response count units are count/bytes; CPU is cpu_seconds; RSS is bytes; latencies/startup are ms. Duplicate metric IDs, wrong units or inconsistent paired sample counts invalidate the record. Missing values are null, never zero. Raw per-trial samples include every required metric; the compact legacy p95/memory trial fields do not substitute for those samples.

## Deterministic outcome mapping

| Claim / evidence | Outcome |
| --- | --- |
| IMPROVEMENT: all required ratio upper bounds strictly <1 and complete controls | NON_REGRESSION (legacy label; report explicitly claims strict improvement) |
| NON_INFERIORITY: all upper bounds ≤ approved relative limits >1 | APPROVED_BUDGET |
| APPROVED_BUDGET: all upper bounds ≤ their approved absolute/relative limits (strict limits, if selected, use <1) | APPROVED_BUDGET |
| Complete evidence: at least one lower bound strictly exceeds its approved upper acceptance limit | REGRESSION |
| Missing/insufficient evidence, violated measurement controls/error budget, overlapping interval or equality under strict improvement | INCONCLUSIVE |

Known complete regression evidence may be reported while another metric is inconclusive, but no accepted outcome may omit an unresolved required metric. For strict improvement an exact interval [1,1] is INCONCLUSIVE, not demonstrated slowdown. For a positive non-inferiority margin, equal/noisy samples whose upper bound satisfies that margin can be accepted. No claim is silently weakened. Stop after the measurement budget and request a reviewed claim/method/budget change instead of retrying forever. Required INCONCLUSIVE/REGRESSION blocks release unless a successor explicitly scoped approval changes requirements; correctness UNKNOWN is never converted.

Structural schemas express policy identity, typed metrics and minimum trial shape. The engine must recompute intervals/outcomes from pinned raw samples and validate all requirements; a producer's confidence_intervals object or declared outcome is not authority. X33/X59 test equal/noisy values, known slowdown, insufficient p99, zero denominators, error omission, missing counters and a policy changed after approval. Runtime/statistical validation remains pending.

For a reviewed not-applicable policy, RELEASE.benchmark_ref names that exact typed policy instead of a benchmark, and the service verifies its membership in the approved PLAN plus its rationale/evidence. The release displays NOT_APPLICABLE and makes no performance claim. Applicable policies require a current accepted benchmark 2.2 at that field. This preserves the existing reference-shaped approval preimage without inventing a PASS benchmark for missing measurements. Required workload metrics cannot be declared not-applicable merely because acquisition failed.

## Fixed stopping rule and operational SLO

Current performance policy 1.1 binds paired_trials=N and stopping_rule=FIXED_N before measurements; not-applicable policies set both null. Repeated looks, favorable restarts or sequential stopping are not qualified methods. All samples/failed attempts remain retained and recomputable. X78 uses a stream with favorable early intervals and regression at N; only N controls acceptance.

An optional operational_slo_ref binds operational-slo 1.0 independently of the statistical claim. Its supported property is latency percentile and error fraction in **every complete fixed measured window**, anchored at each trial's measured start. The workload fixes the window size, minimum requests, percentile, latency bound and error fraction. Preserve timestamps/monotonic offsets and every request outcome; compute nearest-rank latency over successful requests and errors over all attempts in each window. Insufficient requests, incomplete windows required by the workload, missing samples or unavailable clocks produce UNKNOWN. Any fully observed violating window yields FAIL even if mean trial p99 satisfies its statistical limit. Zero-request windows are UNKNOWN, never zero latency.

Benchmark 2.2 records a separate operational_slo_result with raw_window_samples_ref. Null means no SLO requested and the report makes no operational SLO claim. A requested SLO requires the exact policy ref and independently recomputed PASS in addition to statistical acceptance; FAIL/UNKNOWN blocks its release obligation. This bounds the claim to tested windows, never continuous production uptime/tail guarantees. Initial unsupported SLO/profile combinations are INCONCLUSIVE rather than evaluated by the mean-p99 method. M6 qualification precedes any SLO claim; general sequential statistics stay deferred.
