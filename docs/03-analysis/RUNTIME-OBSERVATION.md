# Runtime observation and mechanism-derived completeness

**Owner:** Capture mechanisms and completeness attestations. Gate 1 and the supported isolated [sandbox](../09-security/SANDBOX.md) are prerequisites. Instrument disposable sealed-source copies, never original source.

## Attestation protocol

[attestation.schema.json](../../specs/observation/attestation.schema.json) identifies profile, capture mechanism, boundary, supported/excluded/escape paths, pinned instrumentation, control tests, closure tests, failure evidence and residual limitations. Engine derives COMPLETE only when every required mechanism has CLOSED coverage, valid current controls, no uncontained escape/failure and all applicable dimensions captured within limits. PARTIAL/UNAVAILABLE otherwise; NOT_APPLICABLE requires an approved contract justification. Observer/agent-supplied COMPLETE is not authority. Capture controls test mechanisms, not universe-wide application completeness.

| Mechanism | Capture / closure requirement | Escape/failure forcing incomplete |
| --- | --- | --- |
| HTTP | Proxy exact request/response/ordered headers, redirects, early exit controls | Truncation, alternate listener/protocol |
| DB | All connection/driver inventory, driver/server diagnostics, transactions plus qualified before/after snapshots | Direct PDO/native/alternate connection not covered; missing read/lock evidence |
| Files | Declared volume snapshots plus OS-supported write containment/monitoring controls | Native writes/unmounted or unmonitored path |
| Cache | Every store/namespace and TTL/lock profile, snapshots/operations | Hidden Redis namespace/connection |
| Queue | Broker publish/consume/ack/retry IDs and sink receipts | Uncorrelated worker, missing ack/dead-letter/delivery boundary |
| Session | Safe driver/store capture and lifecycle controls | Opaque serialization, shutdown/write bypass |
| External | Denied real egress plus controlled HTTP/SMTP/etc sinks | Unknown DNS/native protocol or unmatched endpoint |
| Worker | Owned process and job causal propagation, exit/ack boundary | Detached/unowned process or after-boundary effect |
| Cron | Operational schedule/timezone inventory and explicit harness runs | Missed schedule, undeclared environment |
| CLI | Controlled executable/args/stdout/stderr/exit and inherited context | Unsupported subprocess/command escape |
| Generated code | Safe capture of generated bytes and executed path identities | eval/unavailable generated source |
| Native extension | Explicit OS/network/store controls and declared capability | Probe-only visibility or opaque native effects |

Queue/worker/cron/CLI/native/generated mechanisms map to applicable public completeness dimensions (external/execution/files/database etc); they do not disappear because a trace has only HTTP fields. Required mappings live in the approved observation profile. The first supported subset may block unsupported mechanisms; an empty array cannot represent unavailable capture as no effects.

## Trace and causality

Current trace 2.1 requires [causality.schema.json](../../specs/observation/causality.schema.json), profile/reset refs and attestation refs. Envelope: project, execution run/operation, workflow instance, request, process, trace/span/parent, cause IDs, job/effect IDs; explicit null only for genuinely absent relationships. Every child span belongs to its run/project; causal references resolve. Source and target use separate physical trace/process IDs with one logical workflow/case binding. Timestamps order display, never prove causation. Workers inherit envelope via trusted harness/broker metadata, with receipt/ack spans linked to initiating effect. Missing propagation makes dependent async evidence incomplete.

Bodies/logs/screenshots/AST-derived diagnostics are potentially sensitive and sanitized before agent-readable storage. Private fixture/source identity remains separate. Store bounded summaries, hashes and artifact refs; raw trace quotas/retention follow [ARTIFACT-STORE](../08-storage/ARTIFACT-STORE.md). Sampling/truncation invalidates required absence claims. HTTP_RESPONSE completion is valid only for proven synchronous scope; otherwise use acknowledged/quiescent boundary.

At least three restored source repetitions identify variability candidates, not automatic normalizers. Compare instrumented/uninstrumented controls; perturbation remains a finding. Failure/cancellation retains partial sanitized evidence and blockers; never manufacture completeness to continue.

Pre-contract observation traces use scenario_id and case_id=null; verification traces use case_id and optional originating scenario_id. At least one is present and resolves to its input/case record. SQL observations.case_id remains null before a case exists; later case_results links the immutable source observation without rewriting its historical identity.

## Current versus historical attestation records

Current acceptance requires attestation version 2.1. Version 2.0 remains historical-readable; structural validation of its former shape cannot establish current completeness. An unavailable mechanism can have instrumentation_ref=null, no supported paths and empty control/closure arrays, with explicit residual limitations. This represents missing evidence honestly. CLOSED requires a pinned instrumentation ref, nonempty supported paths and control/closure references, and no failure refs. COMPLETE requires every mechanism CLOSED; PARTIAL requires an actually partial/unavailable mechanism; UNAVAILABLE contains only unavailable mechanisms. NOT_APPLICABLE has no mechanism entries and requires a contract justification ref.

These shape constraints are necessary, not sufficient. The service verifies same-project current profile/instrumentation/control identities, resolves each control and closure result, checks required mechanism inventory/escape paths and derives the aggregate status. A renamed/direct driver, native IO or unknown operational root invalidates closure even if an imported producer claims COMPLETE. No applicable required dimension can disappear through NOT_APPLICABLE. Diagnostic controls and partial attestations can support a completed assessment; they cannot support verification PASS or automatic omission.

## Source-local publication and trusted execution witnesses

Current capture uses trace 2.1 and effects 2.1. Publish a side-local identity ledger 1.0 before effects/context/trace; it requires an observation attempt and logical occurrence, not a case/target. Its immutable entries name side/local_id/kind, qualified resource/actor partition, exact typed observed value, relationship refs, capture channel and evidence. Values are side-local; repeated captures can retain entity continuity only with explicit evidence. One local entity maps to one value per identity domain/time epoch; session rotation creates a new identity linked to the old, never overwrites it. Empty identities require positive capture evidence, not invented placeholder target values. Later verification identity-map 2.1 references both ledgers and derives a bijection within declared entity domains/actor partitions. Ambiguity produces UNKNOWN; duplicate indistinguishable rows never pair by order alone. Original ledgers/traces remain unchanged.

Every measured execution carries execution-witness 1.0: side, original content/variant or target tree ref, generated manifest, build artifact, exact loaded executable/image, launch identity (host boot/process start/container), runtime/environment/reset/instrumentation, endpoint binding and independent control refs. The trusted supervisor/runner derives this chain and verifies the actual launched bytes, mount/image digest and bound endpoint. Interpreted profiles restart workers and invalidate/disable opcode cache under a control; a requested tree hash or application self-reported version is insufficient. Target witness pins approved plan/model plus current implementation tree; changing implementation invalidates old runs, not the immutable implementation plan. SOURCE witness cannot serve as TARGET, even if both runtimes use identical technology. Stale/wrong build/endpoint witness blocks contribution to PASS (UNKNOWN/ERR_STALE_EXECUTION), not a semantic mutant kill.

Capture channels are qualified against escape controls and outside application-controlled logs where independent measurement is required. App-written "principal=A" is not authentication evidence. Private authentication instrumentation must correlate actual session lookup and DB principal through controlled negative cases. Redacted public projections retain only safe identities/relations. Execution witness and local identity ledger precede traces, avoiding future-report reference cycles.

Completeness covers application and service processes: DB server/triggers/routines/other connections, cache, queues, workers, native helpers and filesystem services. Framework hooks alone cannot close DB_WRITE. Inspect actual server state/transactions and egress for indirect writes; unknown service connections/causes leave affected dimensions incomplete. Typed payload and delivery occurrence capture follows COMPATIBILITY-SPEC. Async boundary claims name an observation window and schedule horizon; pending out-of-window jobs are explicit unsupported obligations, never proof of no future effects.

Trace 2.1 observation_window records start/end, schedule_horizon_ms, queue_state_ref, due_beyond_horizon and control_refs. End must follow start under the controlled clock; profile completion binds the admitted timeout/horizon. Initial synchronous horizon is zero only with proven synchronous closure; queued work requires inspected state. Required out-of-window effects remain UNKNOWN/unsupported. execution-witness.role_isolation_ref resolves an existing qualification record whose control suite tests rwt-model-roles-1 handle separation; it is not a self-authored assertion. Contexts reference prior capture fragments; step/effect occurrence publication follows the acyclic order in EVALUATION-CONTEXT.

Current side-local identity values are exact scalar string/integer; an unobserved or unsupported identity is not minted as a ledger entry. Pairwise 2.1 bindings name source_local_id/target_local_id resolved in the two referenced ledgers. The legacy map value_type spelling maps losslessly to context/ledger type; values must equal the referenced entries exactly, with no coercion or guessed ordering. Enforce injectivity per domain/resource/actor/session epoch and declared relations across dimensions. Broader composite identity matching requires a qualified future capability.
