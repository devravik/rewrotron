# Runtime observation and mechanism-derived completeness

**Owner:** Capture mechanisms and completeness attestations. Gate 1 and the supported isolated [sandbox](../09-security/SANDBOX.md) are prerequisites. Instrument disposable sealed-source copies, never original source.

## Attestation protocol

[attestation.schema.json](../../specs/observation/attestation.schema.json) identifies profile, capture mechanism, boundary, supported/excluded/escape paths, pinned instrumentation, control tests, closure tests, failure evidence and residual limitations. Engine derives COMPLETE only when every required mechanism has CLOSED coverage, valid current controls, no uncontained escape/failure and all applicable dimensions captured within limits. PARTIAL/UNAVAILABLE otherwise; NOT_APPLICABLE requires an approved contract justification. Observer/agent-supplied COMPLETE is not authority. Capture controls test mechanisms, not universe-wide application completeness.

| Mechanism | Capture / closure requirement | Escape/failure forcing incomplete |
| --- | --- | --- |
| HTTP | Proxy exact request/response/ordered headers, redirects, early exit controls | Truncation, alternate listener/protocol |
| DB | All connection/driver inventory, driver/server diagnostics, transactions plus qualified before/after snapshots | Direct PDO/native/alternate connection not covered; missing read/lock evidence |
| Files | Declared volume snapshots plus OS-supported write containment/monitoring controls | Native writes/unmounted or unmonitored path |
| Cache | Every store/namespace and TTL/lock profile, snapshots/operations | Hidden Redis namespace/connection |
| Queue | Broker publish/consume/ack/retry IDs and sink receipts | Uncorrelated worker, missing ack/dead-letter/delivery boundary |
| Session | Safe driver/store capture and lifecycle controls | Opaque serialization, shutdown/write bypass |
| External | Denied real egress plus controlled HTTP/SMTP/etc sinks | Unknown DNS/native protocol or unmatched endpoint |
| Worker | Owned process and job causal propagation, exit/ack boundary | Detached/unowned process or after-boundary effect |
| Cron | Operational schedule/timezone inventory and explicit harness runs | Missed schedule, undeclared environment |
| CLI | Controlled executable/args/stdout/stderr/exit and inherited context | Unsupported subprocess/command escape |
| Generated code | Safe capture of generated bytes and executed path identities | eval/unavailable generated source |
| Native extension | Explicit OS/network/store controls and declared capability | Probe-only visibility or opaque native effects |

Queue/worker/cron/CLI/native/generated mechanisms map to applicable public completeness dimensions (external/execution/files/database etc); they do not disappear because a trace has only HTTP fields. Required mappings live in the approved observation profile. The first supported subset may block unsupported mechanisms; an empty array cannot represent unavailable capture as no effects.

## Trace and causality

Current trace v2 requires [causality.schema.json](../../specs/observation/causality.schema.json), profile/reset refs and attestation refs. Envelope: project, execution run/operation, workflow instance, request, process, trace/span/parent, cause IDs, job/effect IDs; explicit null only for genuinely absent relationships. Every child span belongs to its run/project; causal references resolve. Source and target use separate physical trace/process IDs with one logical workflow/case binding. Timestamps order display, never prove causation. Workers inherit envelope via trusted harness/broker metadata, with receipt/ack spans linked to initiating effect. Missing propagation makes dependent async evidence incomplete.

Bodies/logs/screenshots/AST-derived diagnostics are potentially sensitive and sanitized before agent-readable storage. Private fixture/source identity remains separate. Store bounded summaries, hashes and artifact refs; raw trace quotas/retention follow [ARTIFACT-STORE](../08-storage/ARTIFACT-STORE.md). Sampling/truncation invalidates required absence claims. HTTP_RESPONSE completion is valid only for proven synchronous scope; otherwise use acknowledged/quiescent boundary.

At least three restored source repetitions identify variability candidates, not automatic normalizers. Compare instrumented/uninstrumented controls; perturbation remains a finding. Failure/cancellation retains partial sanitized evidence and blockers; never manufacture completeness to continue.

Pre-contract observation traces use scenario_id and case_id=null; verification traces use case_id and optional originating scenario_id. At least one is present and resolves to its input/case record. SQL observations.case_id remains null before a case exists; later case_results links the immutable source observation without rewriting its historical identity.
